Technical Architecture and Stack

How OLI-it.Web is built, what cannot change, and where contributors should plug in safely.

Overview home At a glance Matchmaking deep dive

Executive summary

Razor Pages on .NET 10, EF Core database-first over an existing SQL schema, and SQL-native matchmaking logic kept in stored procedures.

Layer map

  • UI: Pages/
  • Business logic: Services/
  • Data access: Data/ + Models/
  • API endpoints: Endpoints/
  • Azure infra: infra/

Non-negotiable constraints

  • ADR-0001 Database-first schema ownership
  • ADR-0002 Matchmaking stays in SQL stored procedures
  • ADR-0003 German schema naming preserved

Contributor guardrails

  • Follow Pages -> Services -> Data.
  • Do not hand-edit scaffolded entities.
  • Keep domain naming exact (`Stamm`, `PostIt`, `TopLab`, ...).
  • Treat ADRs as hard boundaries for design changes.
