What the engine does

It evaluates whether Code (sender intent) and Angler (recipient intent) are mutually compatible, then stores valid pairs in Spiegel.

Core procedures

  • oli.beissen: single pair match/no-match decision
  • oli.fischen: set orchestration + Spiegel synchronization

Decision flow

  1. Require markings on both sides.
  2. Apply strict rules (3) both directions.
  3. Apply flexible-but-required rules (2, threshold >= 2) both directions.
  4. Accept only if both sides satisfy each other's requirements.

Persistence contract

0 match => row exists in Spiegel

-1 no match => row removed from Spiegel

Engineering boundary

Do not move matchmaking logic into C#. Behavior changes should be treated as SQL procedure and ADR-level changes.
